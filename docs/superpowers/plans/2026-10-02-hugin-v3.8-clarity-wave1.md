# Hugin v3.8 wave 1 (card descriptions, card order, «Følger med») Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A first-time visitor can read what each dashboard card is for, the cards run action first and sources last, and «Aktiv» no longer means two things.

**Architecture:** Web-only markup and i18n changes in the dashboard cards, plus one C# helper. The CLI status label moves from the private `Program.StatusLabel` in `Hugin.Console` into `Hugin.Core/Cli/CliLabels.cs`, because `Hugin.Tests` references Core but not Console, so the label cannot be tested where it lives today. No data, API, migration or routing change.

**Tech Stack:** React 19 + TypeScript 7 + Vite; Vitest + Testing Library (jsdom); Biome. C#/.NET 10 with NUnit for the CLI label.

**Spec:** `docs/specs/2026-10-02-hugin-v3.8-clarity.md` (Part A, and the wave 1 half of Part C). Wave 2 (Part B: logo link, footer, version plumbing, open-ad filter, «Nytt siden sist» links) is **not** in this plan. It builds on the reviewer's React Router PR, whose route API does not exist yet, so its plan is written after that PR is merged.

## Global Constraints

- Branch: `feat/v3.8-clarity` (already holds the spec commit `f8c7a36`). One PR for wave 1.
- Rename the label, not the data: the stored status, the API slug `active`, the CLI input `hugin track <orgnr> active`, the export flag `--include-active` and the JSON export stay unchanged. No migration.
- «Aktiv» keeps one meaning: an open ad. «aktive annonser», «Aktive frister» and the export's «Aktiv» ad section stay as they are.
- Card order: `SyncHeader`, `NeedsAction`, `DeadlineList`, `NewSinceLastVisit`, `SourcesCard`.
- Each description is a `<p className="text-muted">` directly under its card's `<h2>`. Plain text, no `aria-describedby`, no new spacing token. The sync strip gets no description.
- nb and en i18n tables keep identical key sets (the parity test in `src/i18n/index.test.ts` enforces it).
- All code, identifiers and comments in English. No em dashes in code, comments, docs, commits or the PR.
- Commits carry no `Co-Authored-By` or AI attribution. Written in first person.
- Repo files have no BOM. Keep each file's own line endings (`* text=auto` normalises to LF in the repo).
- Tests first in every task. The tree is green (web tests, Biome, `tsc -b`, C# tests) after every task.

## Review Focus

1. **The NeedsAction description sits on a warning-tinted alert, not a card.** `.text-muted` may fall under 4.5:1 there even if it passes on the card background, which is the only background the spec names. Pinned by the Task 4 live measurement, which reads contrast on both backgrounds in both themes.
2. **A watched ad's badge in Frister is where a person sees the status label most.** It renders through `pipelineLabel`, which no existing test asserts on for `active`. Pinned by a Task 2 test in `DeadlineList.test.tsx`.
3. **The export option «Inkluder aktive» / "Include active" means the pipeline status.** The spec's A3 table missed it, and leaving it would keep a second meaning of «aktiv». Pinned by Task 2: renamed, added to the guard test, `ExportView.test.tsx` updated.
4. **A card that fails to load must still explain itself.** A description wired into the data branch would vanish in the error state. Pinned by a Task 1 test with `/api/new` answering 500.
5. **On most days NeedsAction renders nothing.** Frister must then sit directly under the sync strip with no empty slot. Pinned by a Task 1 order test without a watched ad.

```js
// The warning alert's background is translucent (--warning-soft is 16 % alpha in dark, 12 % in
// light), so every translucent layer is composited over the first opaque one below it.
// Reading the alert's colour as if it were opaque would report a wrong contrast.
const parse = (css) => {
  if (!css.startsWith('rgb')) throw new Error(`unparsed colour ${css}`)
  const n = css.match(/[\d.]+/g).map(Number)
  return { rgb: n.slice(0, 3), a: n.length > 3 ? n[3] : 1 }
}
const bgOf = (el) => {
  const layers = []
  for (let n = el; n; n = n.parentElement) {
    const c = parse(getComputedStyle(n).backgroundColor)
    if (c.a > 0) layers.push(c)
    if (c.a === 1) break
  }
  const base = layers.pop()
  if (!base || base.a !== 1) throw new Error('no opaque background found')
  return layers
    .reverse()
    .reduce((rgb, layer) => rgb.map((c, i) => c * (1 - layer.a) + layer.rgb[i] * layer.a), base.rgb)
}
const lum = (rgb) => {
  const [r, g, b] = rgb.map((c) => {
    c /= 255
    return c <= 0.03928 ? c / 12.92 : ((c + 0.055) / 1.055) ** 2.4
  })
  return 0.2126 * r + 0.7152 * g + 0.0722 * b
}
;[...document.querySelectorAll('section h2 + p.text-muted')].map((p) => {
  const h = p.previousElementSibling.getBoundingClientRect()
  const r = p.getBoundingClientRect()
  const [l1, l2] = [lum(parse(getComputedStyle(p).color).rgb), lum(bgOf(p))].sort((a, b) => b - a)
  return {
    card: p.previousElementSibling.textContent,
    gapPx: Math.round(r.top - h.bottom),
    contrast: ((l1 + 0.05) / (l2 + 0.05)).toFixed(2),
  }
})
```
