# Hugin v3.3 — Focus Filters + Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the v3.2 small-bug batch (plurals, silent dashboard errors, two races, API robustness), then add a fylke → kommune cascading filter to Companies and a persisted, app-wide "focus" chosen via a first-run dialog.

**Architecture:** Frontend-only except Task 5 (two tiny API guards). Part A patches existing views in place. Part B adds a static fylke module and one more select to BedrifterView. Part C adds a `focus.tsx` module (localStorage + validation + React context owned by App) consumed by the dashboard lists, BedrifterView, Settings, and a new first-run `<dialog>`.

**Tech Stack:** React 19 + TypeScript (Vite, Vitest + Testing Library), ASP.NET Core minimal APIs + NUnit. No new dependencies.

**Spec:** `docs/specs/2026-08-28-hugin-v3.3-focus-filters.md`

## Global Constraints

- Every new user-facing string lands in BOTH `hugin-web/src/i18n/nb.ts` and `en.ts` — the key-parity test fails otherwise. No plural engine: singular text = separate `*One` key chosen in code.
- `design-system/` is read-only. New CSS goes in `hugin-web/src/styles/main.css` only (this wave should need none).
- Frontend tests: `cd hugin-web; npx vitest run <file>` (full: `npm test`). Backend: `dotnet test`.
- Commits: conventional prefixes, no attribution trailers, one commit per task (message given per task).
- Uncategorized / kommune-less data **fails open** everywhere a filter looks at it.
- Ads with a non-null `pipelineStatus` **bypass the focus lens** (a starred entry always has a status, so status covers both).

```ts
/** 2024 fylke set. Static by design: kommune numbers embed the fylke as their first two
 * digits, and this list changes only by national reform. Unknown prefixes fail open
 * under the raw number (fylkeName fallback). */
export const FYLKER: ReadonlyMap<string, string> = new Map([
  ['03', 'Oslo'], ['11', 'Rogaland'], ['15', 'Møre og Romsdal'], ['18', 'Nordland'],
  ['31', 'Østfold'], ['32', 'Akershus'], ['33', 'Buskerud'], ['34', 'Innlandet'],
  ['39', 'Vestfold'], ['40', 'Telemark'], ['42', 'Agder'], ['46', 'Vestland'],
  ['50', 'Trøndelag'], ['55', 'Troms'], ['56', 'Finnmark'],
])

export function fylkeOf(kommunenummer: string | null | undefined): string | null {
  if (!kommunenummer || kommunenummer.length < 2) return null
  return kommunenummer.slice(0, 2)
}

export function fylkeName(nr: string): string {
  return FYLKER.get(nr) ?? nr
}
```

`adMatchesFocus` per the spec (tracked bypass first, then fail-open region/category):

```ts
export function adMatchesFocus(ad, focus) {
  if (!focus) return true
  if (ad.pipelineStatus) return true
  const regionOk =
    !focus.fylke || !ad.kommune
      ? true
      : focus.kommune
        ? ad.kommune === focus.kommune
        : ad.kommune.startsWith(focus.fylke)
  const category = ad.category
  const categoryOk =
    focus.categories.length === 0 || !category
      ? true
      : focus.categories.some((c) => category.includes(c))
  return regionOk && categoryOk
}
```
