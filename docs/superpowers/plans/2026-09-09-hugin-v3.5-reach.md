# Hugin v3.5 "reach" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Widen company discovery from NACE 62 to a curated developer-adjacent set that the user can edit from Settings, stop assuming the user lives in Innlandet, and add a two-level reset.

**Architecture:** Three new API surfaces on the existing minimal-API host — `GET/PUT /api/config/focus`, `GET /api/config/focus/preview`, `POST /api/reset` — plus a `full` parameter on the existing sync endpoint. Config writes reuse v3.4's read-modify-write on the raw JSON document so hand-edited keys round-trip. The dashboard grows one Settings card (Fokus) and one danger section (Nullstilling), both following `CoverageSection`'s patterns. No EF migration.

**Tech Stack:** C# / .NET 10 (`net10.0`), EF Core + SQLite, minimal APIs, NUnit with a custom `ApiFactory` and fakes in `Hugin.Tests/Fakes.cs`; React 19 + TypeScript 7 + Vite + Vitest + Testing Library; Biome for web lint/format.

**Spec:** `docs/specs/2026-09-09-hugin-v3.5-reach.md`

## Global Constraints

- **Branch:** `feat/v3.5-reach`, cut from `main`. Commit after every task.
- **Commit messages:** conventional commits in English (`feat:`, `fix:`, `docs:`, `test:`, `chore:`), scope in parentheses where it helps (`feat(web):`). **Never add a `Co-Authored-By` trailer or any AI-attribution line.**
- **Line endings:** the working copy is CRLF for `.cs` and `.md` (`.gitattributes` is `* text=auto`, `core.autocrlf=true`). Any scripted edit must read and write bytes and preserve each file's existing endings. No BOM anywhere.
- **UI strings live in both `hugin-web/src/i18n/nb.ts` and `en.ts`.** `TranslationKey = keyof typeof nb`, so a key added to `nb.ts` and missed in `en.ts` is a type error. Norwegian is the source language.
- **Security model, unchanged:** loopback bind, Host allowlist, every non-GET under `/api` needs `X-Hugin: 1`, no CORS, public mode refuses every write. Task 6 adds the one named exception for a side-effecting GET.
- **Validation regex for a NACE code:** `^\d{2}(\.\d{1,3})?$`. Used identically in `PUT /api/config/focus` and in the preview.
- **Caps:** at most 50 codes and 200 keywords, each at most 40 characters.
- **Curated default codes (verbatim):** `62`, `72`, `63`, `58.2`, `64.19`, `92`, `61`, `26.2`.
- **Snapshot filename:** `hugin.db.reset-<yyyyMMdd-HHmmss>.bak` — the `hugin.db` prefix is load-bearing (existing ignore and packaging filters use `hugin.db*`).
- **Verification before any completion claim:** `dotnet build` (0 warnings), `dotnet test`, and in `hugin-web/`: `npm run test`, `npx biome check .`, `npx tsc -b`.

## Test helpers that already exist — verified 2026-09-09

Read this before writing a single test. These are the real shapes; do not invent alternatives.

- **`Hugin.Tests/Api/ApiFactory.cs`** is a `WebApplicationFactory<Program>` with a **primary
  constructor taking positional flags**: `new ApiFactory(autosync: false, existingDb: false,
  publicMode: false)`. It has no settable properties — `new ApiFactory { Config = ... }` does not
  compile.
- **There is no config hook.** The factory registers a real `HuginConfigFile` at
  `factory.ConfigPath` inside a temp directory. To give a test a specific config, **write the JSON
  to `factory.ConfigPath` before creating the client**, exactly as `ConfigEndpointTests.cs:181`
  does. A missing file means "fresh install", which several tests assert with
  `File.Exists(factory.ConfigPath) Is.False`.
- The factory *also* registers a singleton `HuginConfig` (carrying one linkout, so `/api/status`'s
  passthrough is observable). That singleton is a fixed snapshot — anything that must see a live
  config edit has to read through `IConfigSource`/`HuginConfigFile`, never the singleton.
- **`factory.CreateApiClient()`** returns a client with `X-Hugin: 1` already set. Use it for every
  write; use plain `CreateClient()` only when a test needs the header *missing*.
- **Seeding rows** goes through a scope — `using var scope = factory.Services.CreateScope();` then
  `scope.ServiceProvider.GetRequiredService<ICompanyRepository>()`, as in
  `ExtractEndpointTests.cs:30`. There is no `SeedAsync`, and no way to restart a host over the same
  database file (`DbPath` is per-factory).
- **Waiting for a sync** uses the local `PollUntilFinished(client)` helper in
  `Hugin.Tests/Api/SyncEndpointTests.cs`, which polls `GET /api/sync/status` until
  `SyncRunStatus.Running` is false. There is no `WaitForSyncAsync`.
- **`FakeNavFeedClient`** takes `params FeedPage[]` and exposes `RequestedCursors`,
  `RequestedScopes`, `OnCall`, and **`FirstPageRequested` as a `bool`** — not a counter.
- **`FakeBrregClient`** exposes `Companies`, `ByOrgnr`, `Kommuner`, `CompaniesRequests`,
  `ByOrgnrRequests`, `Throws`, `ThrowsOnGetByOrgnr`, `ThrowsOnGetKommuner`,
  `ThrowOnCompaniesCallNumber`, `OnCall`. Task 7 adds `Counts` and `CountRequests`.
- **`SyncServiceTests` has no fixture class.** It uses a private `record Harness(...)` built by a
  static `Build(brreg:, nav:, ads:, companies:, prober:, config:, kommuner:)` that wires a
  `FakeConfigSource`. Pass a config as `Build(config: new HuginConfig { ... })`.
- **`HuginDbContext`** DbSets: `Companies`, `Ads`, `Pipeline`, `SyncStates`, `ReviewMarks`,
  `Kommuner`, `Sources`.
- **`HuginDbInitializerTests`** builds its own `HuginDbContext` over a temp path and calls
  `HuginDbInitializer.InitAsync(db)` directly. That is the home for the "a reset must not resurrect
  the seeded sources" regression test, which needs a second init over the same file.
- **Web tests**: copy the fetch-mocking setup from
  `hugin-web/src/components/CoverageFields.test.tsx` into the new test files. The `server.get(...)`

- [ ] **Step 4: Refactor the writer and add `WriteFocus`**

In `HuginConfigFile`, extract the body of `WriteDiscovery` after its key list into:

```csharp
    private static readonly string[] FocusKeys = ["naeringskoder", "keywords"];

    public FocusConfig ReadFocus() => FocusConfig.From(Load());

    public void WriteFocus(FocusConfig focus) => WriteKeys(FocusKeys, root =>
    {
        root["naeringskoder"] = new JsonArray(focus.Naeringskoder.Select(c => (JsonNode)JsonValue.Create(c)!).ToArray());
        root["keywords"] = new JsonArray(focus.Keywords.Select(k => (JsonNode)JsonValue.Create(k)!).ToArray());
    });

    /// <summary>Re-reads the file, drops every case-variant spelling of <paramref name="keys"/>
    /// (the loader matches case-insensitively, so a hand-written "Keywords" would keep winning
    /// beside a new "keywords"), applies the caller's writes, then backs up and replaces
    /// atomically. Everything else in the document round-trips.</summary>
    private void WriteKeys(string[] keys, Action<JsonObject> apply)
    {
        JsonObject root;
        try
        {
            root = File.Exists(ConfigPath)
                ? JsonNode.Parse(File.ReadAllText(ConfigPath), documentOptions: ReadOptions) as JsonObject ?? new JsonObject()
                : new JsonObject();
        }
        catch (JsonException ex)
        {
            throw new JsonException(ex.Message, innerException: ex);
        }

        foreach (var key in root.Select(p => p.Key).Where(k => keys.Contains(k, StringComparer.OrdinalIgnoreCase)).ToList())
            root.Remove(key);

        apply(root);

        var json = root.ToJsonString(WriteOptions);
        if (File.Exists(ConfigPath)) File.Copy(ConfigPath, ConfigPath + ".bak", overwrite: true);
        var tmp = ConfigPath + ".tmp";
        File.WriteAllText(tmp, json);
        File.Move(tmp, ConfigPath, overwrite: true);
    }
```

Then rewrite `WriteDiscovery` to call `WriteKeys(DiscoveryKeys, root => { ... })` with its three existing assignments, so the backup and atomic-replace dance exists once.

```csharp
using Hugin.Core.Config;
using Hugin.Infrastructure;
using Hugin.Infrastructure.Data;
using Microsoft.EntityFrameworkCore;

namespace Hugin.Api.Services;

/// <summary>
/// Two levels of starting over (spec v3.5 Part D). "scope" clears the geography and leaves
/// everything else; "all" also empties the data, after taking a consistent snapshot.
/// </summary>
public sealed class ResetService(HuginDbContext db, HuginConfigFile file, IClock clock)
{
    public void ClearScope() =>
        file.WriteDiscovery(new DiscoveryConfig([], [], false));

    /// <summary>
    /// Order matters and is not negotiable: SQLite refuses VACUUM and VACUUM INTO inside a
    /// transaction, so the snapshot and the compaction sit outside the one that deletes rows.
    /// The file itself is never deleted — this process holds it open.
    /// </summary>
    public async Task<string> WipeAsync(CancellationToken ct = default)
    {
        var dbPath = file.DatabasePath;
        var snapshot = $"{dbPath}.reset-{clock.UtcNow.ToLocalTime():yyyyMMdd-HHmmss}.bak";
        if (snapshot.Contains('\n') || snapshot.Contains('\0'))
            throw new InvalidOperationException("Ugyldig sti for sikkerhetskopi.");

        // VACUUM INTO takes a string literal, not a parameter — double every quote in the path.
        // C:\Users\O'Brien\ is an ordinary Windows path.
        var quoted = snapshot.Replace("'", "''");
        await db.Database.ExecuteSqlRawAsync($"VACUUM INTO '{quoted}';", ct);

        await using (var tx = await db.Database.BeginTransactionAsync(ct))
        {
            await db.Ads.ExecuteDeleteAsync(ct);
            await db.Pipeline.ExecuteDeleteAsync(ct);
            await db.Companies.ExecuteDeleteAsync(ct);
            await db.ReviewMarks.ExecuteDeleteAsync(ct);
            // Selective on purpose: the "sources-seed" row is what stops HuginDbInitializer
            // re-importing the default sources and the config linkouts on the next launch.
            await db.SyncStates.Where(s => s.Source == "brreg" || s.Source == "nav")
                .ExecuteDeleteAsync(ct);
            await tx.CommitAsync(ct);
        }

        await db.Database.ExecuteSqlRawAsync("VACUUM;", ct);
        return snapshot;
    }
}
```

```tsx
  const previewCache = useRef(new Map<string, NacePreviewDto>())

  const preview = async (code: string) => {
    if (!NACE_PATTERN.test(code)) return setPreviewText(t('focus.previewFailed'))
    const cached = previewCache.current.get(code)
    const result = cached ?? (await api.get<NacePreviewDto>(
      `/api/config/focus/preview?nace=${encodeURIComponent(code)}`
    ).catch(() => null))
    if (!result) return setPreviewText(t('focus.previewFailed'))
    previewCache.current.set(code, result)
    const text = result.units === 0 || !result.name
      ? t('focus.previewUnknown', { code: result.code })
      : t('focus.previewResult', { code: result.code, name: result.name, units: String(result.units) })
    setPreviewText(text)
    announce(text)
  }
```
