# Hugin v3.2 — Feedback Wave + Branding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement all 10 items of my v3.0.0 release feedback — db-backed customizable header sources + Settings view, browser back/forward, companies declutter with branches-as-tabs, professional filter controls, the 12 parked leftovers, and the full Hugin brand.

**Architecture:** Backend adds one new entity (`Source`) with repository + minimal-API CRUD, seeded once from defaults + `hugin.json` linkouts; the frontend gets a path-based History-API route layer over the existing keep-mounted view state, a Settings view that owns source CRUD, and a rework of the companies list/detail (tabs). No new libraries anywhere.

**Tech Stack:** C#/.NET 10, EF Core + SQLite, NUnit 4, ASP.NET Core minimal API · React 19 + TypeScript, Vite, Vitest 4, zero runtime deps · design-system 3.0.0 (`data-palette="hugin"`).

**Spec:** `docs/specs/2026-08-24-hugin-v3.2-feedback.md` (single source of truth; item numbers below refer to it).

## Global Constraints

- Web layouts center on screen and scale automatically. Mobile-first CSS (`min-width` queries only; tablet 768px, desktop 1024px).
- Dark-first with the light variant maintained — verify both themes for every visual change.
- i18n parity nb/en: every new UI string gets a key in BOTH `hugin-web/src/i18n/nb.ts` and `en.ts` (runtime key-parity test enforces this).
- Raw data stays raw in db and exports.
- No `Co-Authored-By` or Claude attribution in commits (overrides default template).
- Branch → PR → stop. Merge/release only on my word. Work on branch `feat/v3.2-feedback`.
- Frontend tests: `cd hugin-web; npm test` (vitest, 109 green today). Backend: `dotnet test` (NUnit, 244 green today). Both must be green at every commit.
- EF migrations: `dotnet tool restore` once, then `dotnet ef migrations add <Name> --project Hugin.Infrastructure --startup-project Hugin.Infrastructure --output-dir Data/Migrations`. (Older docs/plans show `--startup-project Hugin.Console` — stale, do not copy.)
