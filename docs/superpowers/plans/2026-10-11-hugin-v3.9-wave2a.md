# Hugin v3.9 wave 2a (open-ad filter, place counts, version in /api/status) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The company list can answer "who is hiring right now?", «Nytt siden sist» counts per place and groups new ads by place, and `/api/status` reports the version the publish build stamped from the git tag.

**Architecture:** Server first, web second. A new grouped query `IAdRepository.CountOpenByEmployerAsync` feeds `CompanyDto.OpenAds` on every endpoint that builds a `CompanyDto`. One shared place-name rule (`PlaceName.Resolve`) feeds both `CompanyDto.KommuneNavn` and the new `AdDto.KommuneNavn`. The version is an MSBuild property (`dev` by default) that `build.ps1` and `publish-demo.ps1` override from `git describe`, and `/api/status` reads it from the API assembly. On the web, `CompaniesView` gains one select and a muted count per row, and `NewSinceLastVisit` gains a place heading with counts for both companies and ads. No routing, no `App.tsx`, no data-fetching change.

**Tech Stack:** C#/.NET 10, ASP.NET Core minimal APIs, EF Core + SQLite, NUnit 5. React 19 + TypeScript 7 + Vite, Vitest + Testing Library (jsdom), Biome. PowerShell 7 for the build scripts.

**Spec:** `docs/specs/2026-10-02-hugin-v3.8-clarity.md`: B3 (server and scripts only), B4 (all), B5 (place counts and ad grouping only), the wave 2 half of Part C, and the stress-test record. Task 1 adds the dated «Release split (2026-10-11)» section that defines wave 2a and 2b.

**Out of this plan (wave 2b, after the reviewer's router PR):** B1 logo link, B2 footer and the web `StatusDto.version` field, the router half of B5 (company names as links, close returns to where it was opened). `App.tsx` is not touched.

## Review Focus

1. **An ad on its deadline day is still open.** NAV's `expires` is end of day, so an ad whose `Expires` equals now must count, exactly as Frister shows it. A `>` where `>=` belongs would quietly drop every company whose only ad closes today. Pinned in Task 3 (`deadline-today` in the repository test).
2. **A hand-linked ad must not make a second company look like it is hiring.** The spec rejects counting `LinkedOrgnr` but lists no test for it. Pinned in Task 3: an ad from employer C linked to A counts for C only.
3. **An ad with no employer orgnr has nowhere to count.** NAV's closed-ad stubs and unenriched ads carry a null orgnr. Grouping on it must neither throw nor produce a null key. Pinned in Task 3 (`no-orgnr`).
4. **The ads filter survives opening and closing a company.** A person filters to «Med åpen annonse», opens a company, presses Tilbake and expects the same filtered list with focus on the row. Pinned in Task 5 (regression guard: it passes on state that already survives today, so it is named as a guard, not red-first proof).
5. **A build from a source zip (no `.git`) must not stop.** `git describe` fails outside a checkout, and with `$ErrorActionPreference = "Stop"` a careless call would abort the whole build. Expected: the version reads `dev` and the build goes on. Pinned in Task 2 Step 8, which runs the version snippet from outside the repo.

**Keep the reviewer's rebase small.** The reviewer's coming TanStack Query PR rewrites data fetching in `CompaniesView` and `NewSinceLastVisit` (the `load` callbacks, the `data`/`loaded`/`error` state and the `refreshKey` effects). Wave 2a changes only rendering and filtering in those two components: new state for the select, the filter predicate, the row markup, the result line and the grouping helpers. Do not touch `load`, `useEffect`, `api.get` or the error branches, and do not move code around them. That also means the counts are only as fresh as the list: `App.tsx` keeps every view mounted, and `CompaniesView` fetches once, so hiding an ad in Frister or finishing a sync does not update the open-ad counts until the page reloads. That is the list's existing behaviour, it is named in the PR body, and refetching is the TanStack Query PR's job.

/** Groups items by place, preserving first-seen order of both groups and members. */
function groupByPlace<T>(
  items: T[],
  placeOf: (item: T) => string | null,
  unknownPlace: string
): [string, T[]][] {
  const groups = new Map<string, T[]>()
  for (const item of items) {
    const key = placeOf(item) ?? unknownPlace
    const group = groups.get(key)
    if (group) group.push(item)
    else groups.set(key, [item])
  }
  return [...groups.entries()]
}
