# Hugin v3.7.3 fictional demo seed: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The public demo tracks three fictional firms with one rolling fictional ad each, and no tracked file in the repo names a real business tied to me.

**Architecture:** `DemoSeeder` (Hugin.Api) learns three optional blocks in `demo-pipeline.json` (`svar`, `company`, `ad`). It writes the company and the ad through two new repository methods (`PutSeededAsync`) that set every seeder-owned field on every run, so the dates roll. Each entry is handled on its own, and a failing entry never stops the boot. A separate first task replaces every real business in fixtures, tests, comments and docs with invented data from a local-only map.

**Tech Stack:** .NET 10 (ASP.NET Core, EF Core + SQLite, NUnit 5), React 19 + TypeScript (Vitest, Biome).

**Spec:** `docs/specs/2026-10-08-hugin-v3.7.3-demo-fictional-seed.md`

## Global Constraints

- Fictional orgnr: `100000001`, `100000002`, `100000003`. Real orgnr start with 8 or 9, and a `company` block on such an orgnr is rejected.
- Fictional firms: Mjøskode AS (Hamar `3403`, `active`), Tindebit AS (Lillehammer `3405`, `applied`), Lysbekk Data AS (Gjøvik `3407`, `answered`). NACE `62.100` (SN2025), ad category `IT / Utvikling`.
- Why-line on all three: «Demo: fiktivt firma, sporet for å vise pipelinen.» Lysbekk Data's svar: «Takk for søknaden. Vi gikk videre med andre kandidater.»
- Ad `FeedId` = `demo-<orgnr>`. `Expires` = 23:59:59 UTC on today's UTC date plus `expiresInDays`. `IsActive` = `expiresInDays >= 0`. No `SourceUrl`.
- Seeded company: `FirstSeen` = now minus 60 days on insert, kept on later runs. Not a branch, no parent, no website.
- Pipeline rows: insert once, never update (unchanged rule).
- No em dashes in any new text: code, comments, log lines, i18n strings, commits.
- Keep each file's BOM and line endings: C# = CRLF, web and docs = LF, no BOM. Git Bash `sed -i` strips CRLF; run `unix2dos` on C# files afterwards or use the Edit tool.
- The old-to-new map for Task 1 lives in `docs/superpowers/plans/2026-10-08-hugin-v3.7.3-scrub-map.private.md` (gitignored). Never copy a name from it into a tracked file, a commit message or a PR.

## Review Focus

1. **A typed number in the wrong JSON shape** (`"publishedDaysAgo": "10"` or `2.5`): today one bad value throws `JsonException` for the whole file and the demo seeds nothing. Expected: only that entry is skipped. Pinned in Task 2 (numbers read as `JsonElement`).
2. **A huge day count** (`"expiresInDays": 99999999`): `AddDays` overflows. Expected: that entry is logged and skipped, the boot goes on. Pinned in Task 4 (the date maths runs inside the per-entry `try`).
3. **The demo ad expiring today** (`expiresInDays: 0`): expected open until 23:59:59 UTC, `DaysLeft` 0, still listed. Pinned in Task 4.
4. **A seed edit on a running demo** (name or kommune corrected): expected to land on the next run without touching the pipeline row. Pinned in Task 4.
5. **The shipped `demo/demo-pipeline.json` itself:** a typo there seeds a broken demo with only a warning in a log nobody reads. Expected: a test parses the real file with zero problems. Pinned in Task 5.

```csharp
    /// <summary>Validates the optional blocks. Null = the entry is invalid and one problem line
    /// was added; otherwise the parsed blocks, either of which may be null.</summary>
    private static (DemoSeedCompany? Company, DemoSeedAd? Ad)? ParseBlocks(string orgnr, RawCompany? c, RawAd? a,
        List<string> problems)
    {
        string? problem = null;
        if (a is not null && c is null) problem = "ad-blokk uten company-blokk";
        else if (c is null) return (null, null);
        else if (orgnr[0] is '8' or '9') problem = "company-blokk på et ekte orgnr (starter med 8 eller 9), hoppet over";
        else if (string.IsNullOrWhiteSpace(c.Name)) problem = "company.name mangler";
        else if (c.Kommune is null || !Kommune().IsMatch(c.Kommune)) problem = $"company.kommune «{c.Kommune}» må være fire siffer";
        else if (c.Nace is null || !Nace().IsMatch(c.Nace)) problem = $"company.nace «{c.Nace}» må ha formen NN.NNN";
        else if (a is not null && string.IsNullOrWhiteSpace(a.Title)) problem = "ad.title mangler";
        else if (a is not null && Int(a.PublishedDaysAgo) is not >= 0) problem = "ad.publishedDaysAgo må være et heltall, 0 eller mer";
        else if (a is not null && Int(a.ExpiresInDays) is null) problem = "ad.expiresInDays må være et heltall";

        if (problem is not null)
        {
            problems.Add($"{orgnr}: {problem}");
            return null;
        }

        var company = new DemoSeedCompany(c!.Name!.Trim(), c.Kommune!, c.Nace!);
        return a is null
            ? (company, null)
            : (company, new DemoSeedAd(a.Title!.Trim(), Int(a.PublishedDaysAgo)!.Value, Int(a.ExpiresInDays)!.Value));
    }

    private static int? Int(JsonElement? value) =>
        value is { ValueKind: JsonValueKind.Number } v && v.TryGetInt32(out var n) ? n : null;
```

`Int(...) is not >= 0` is true for null too, so a missing or non-integer `publishedDaysAgo` lands on the same line as a negative one.

    {
