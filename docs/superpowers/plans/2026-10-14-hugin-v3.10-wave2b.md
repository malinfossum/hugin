# Hugin v3.10 wave 2b (logo link, footer, company links from «Nytt siden sist») Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The logo takes me home, a footer shows the version, the repo and the data credit, and every new company in «Nytt siden sist» opens its detail, whose close button brings me back to where I opened it, with focus on the link I came from.

**Architecture:** Web only, on top of the TanStack Router shell from #53. The logo becomes a router `Link` to `/` that shares the nav's per-view search memory. A new `AppFooter` reads `version` from the status query the app already runs at boot. «Nytt siden sist» renders router links, and the companies route closes a detail with `router.history.back()` whenever the app has an earlier history entry (`useCanGoBack()`), falling back to `/companies` on a cold load. Because views now unmount, a small `ReturnFocusProvider` in the shell remembers which link was followed from which history entry, and the dashboard card focuses that link again once its data has rendered on the same entry.

**Tech Stack:** React 19 + TypeScript + Vite, TanStack Router 1.170 and TanStack Query 5, Vitest 5 + Testing Library (jsdom), Biome. No server change: `/api/status` already returns `version` (wave 2a).

**Spec:** `docs/specs/2026-10-02-hugin-v3.8-clarity.md`: B1, B2, the router half of B5, the wave 2 web tests in Part C, «Release split (2026-10-11)» (2b = v3.10.0) and «Router change (2026-10-12)». Task 1 adds «Planning notes, wave 2b (2026-10-14)», which this plan argues from where it differs from the original text.

**Out of this plan:** the company-detail dialog and the shadcn redesign (the contributor's pilot, not started). The close rule lives in the route's `onCloseCompany`, so a dialog can call the same function later. The release itself (tag v3.10.0, zips, demo) is a separate step after the merge, on my go.

## Global Constraints

- Branch: `feat/v3.10-wave2b`, cut from main `d9e7815`. One PR. No tag, no release.
- Logo: a router link to `/`, accessible name «Hugin, til dashbordet» / "Hugin, to the dashboard" (i18n key `brand.homeLabel`). The name starts with the visible word «Hugin». Same `search` as the «Dashbord» nav item would use (the dashboard's last `?show=`). No underline, existing focus ring, hit box at least 44 px tall.
- Footer: `<footer className="app-footer">` after `<main>`, inside `.app-shell`. Content: `Hugin <version>` (left out when the status fetch failed), `GitHub` linking to `https://github.com/malinfossum/hugin`, and «Annonser fra NAV · Bedriftsdata fra Brønnøysundregistrene (NLOD)» / "Ads from NAV · Company data from the Brønnøysund Register Centre (NLOD)". «NLOD» links to `https://data.norge.no/nlod/no/2.0` in bokmål and `https://data.norge.no/nlod/en/2.0` in English. Every footer link: `target="_blank" rel="noopener noreferrer"`, `inline-flex`, `min-block-size: 44px`. Muted, small (`--text-sm`), centred.
- Grid: `.app-shell` rows become `auto 1fr auto`, and `auto auto 1fr auto` with the demo banner. `<main>` keeps the `1fr` row.
- No second status request: the footer reads `useQuery(statusQuery())`, the same key `ReadOnlyProvider` and `SyncHeader` read.
- Company links in «Nytt siden sist»: router `Link` to `/companies/{-$orgnr}` with the company's own orgnr (a branch links to the branch) and empty search. Same tab, no `target`. The branch tag «[avdeling]» stays outside the link, so the link's name is the company name only.
- Close rule: if `useCanGoBack()` is true, close calls `router.history.back()`. Otherwise (a cold load of `/companies/<orgnr>`, history index 0) it navigates to `/companies` with the current search, as today.
- Focus on open: the detail focuses its company heading once per opened company, after its data has rendered, with `{ preventScroll: true }`.
- Focus on return: the link carries `data-return-focus="company:<orgnr>"`. It is focused with `{ preventScroll: true }` so the router's scroll restoration keeps its position, only after the page was really left and the history entry it was followed from is current again, only once the fresh list has rendered, and never when the person has already moved focus. If the company is gone from the list, the card heading takes focus instead. Focus never stays on `<body>`.
- One close per opened company: a repeated close (Enter held down) does not go back twice.
- nb and en i18n tables keep identical key sets (`src/i18n/index.test.ts` enforces it). Norwegian only in i18n; all code, identifiers, test names and comments in English.
- Never edit `hugin-web/design-system/` (shared, read-only). Hugin's overrides live in `src/styles/main.css`.
- Line endings and encoding: edit files in place so each keeps its own EOL, no BOM.
- No em dashes in code, comments, docs, commits or the PR. No en dash or spaced hyphen as a stand-in.
- Commits in the repo's style (`web:`, `docs:`, `test:` prefixes, lower case). No `Co-Authored-By`, no AI attribution.
- Tests first in every task. The tree is green after every task, in `hugin-web`: `npm test`, `npm run lint`, `npx tsc -b`. Baseline on main `d9e7815`: 33 files, 421 tests.

## Review Focus

1. **A cold deep link must not close out of the app.** Someone opens a shared `/companies/<orgnr>` link and presses Tilbake. History has nothing earlier in the app, so Back would leave Hugin. Expected: the company list. Pinned in Task 6 (regression guard: it passes on today's code, so it is named as a guard, not red-first proof).
2. **The browser's own Back button returns focus too, not only Tilbake.** Most people press Back, not the in-page button. Expected: the same link is focused. Pinned in Task 6.
3. **Coming back to the dashboard through the nav is not a return.** Opening a company, then clicking «Dashbord» in the nav, must not pull focus onto the old company link: the person just clicked the nav. Pinned in Task 6.
4. **A failed status fetch must not print «Hugin undefined».** The footer keeps its links and credit and drops only the version. Pinned in Task 3.
5. **The footer must not push `<main>` down on short views, with or without the demo banner.** jsdom cannot measure layout, so this is pinned in the Task 7 live check at 320, 375 and 1280 px against both a normal and a `--public` scratch server.

```markdown
## Planning notes, wave 2b (2026-10-14)

Planning 2b against the code after the router change, and its stress test, turned up six things the text above does
not say, or says differently.

1. **B1 names a nav item that is not there.** The nav item is «Dashbord», not «Oversikt». The
   logo's accessible name is «Hugin, til dashbordet» / "Hugin, to the dashboard", so it matches
   what the nav calls the same place. "Same focus move" now means what the nav does after the
   router change: focus stays on the link that was activated. The live check's "dashboard
   heading focused" is replaced by "focus stays on the logo".
2. **Close goes back whenever the app has an earlier entry.** The router keeps an index on each
   history entry, and the first entry of a visit is 0. Close goes back one step when the index
   is above 0, and to `/companies` otherwise. That covers a detail opened from the list too:
   the list sits on the entry before it, with its filters, and its own row focus keeps working.
3. **Focus returns by identity, and Back counts too.** The followed link is remembered as
   `company:<orgnr>` together with the history entry it was followed from. When that entry is
   current again, by Tilbake or by the browser's Back, «Nytt siden sist» focuses the link once
   its list has rendered, without scrolling (the router restores the scroll position). Reaching
   the dashboard any other way, such as through the nav, is a new entry and focuses nothing. It
   waits for the list's refetch, so a company that is no longer new is not focused for a moment
   and then lost: the card heading takes focus instead. It never moves focus the person has
   already moved, and a Ctrl-click that opened a new tab is not a return.
4. **The version reads whatever the build stamped.** On the v3.10.0 release the footer reads
   `Hugin v3.10.0`, and `Hugin dev` under `npm run dev` and in tests.
5. **Opening a company moves focus to its heading.** Opening replaces the page under the
   focused row or link, so focus fell to `<body>` and a screen reader heard nothing. That was
   already true from the list; the new links add a second way in. The detail focuses its company
   heading once per opened company, after its data has rendered, without scrolling.
6. **Close runs once.** Enter held down on Tilbake repeats the click before the first Back has
   rendered. A second Back would go a page too far, out of the app from a visit's first page.
```

- [ ] **Step 6: Write the component**

Create `hugin-web/src/components/AppFooter.tsx`:

```tsx
import { useQuery } from '@tanstack/react-query'
import { useLang, useT } from '../i18n'
import { REPO_URL } from '../lib/links'
import { statusQuery } from '../lib/queries'

/** NLOD 2.0 in the reader's language (both checked 2026-10-02). Brreg names NLOD as its licence
 * and NLOD asks for a source credit; NAV names no licence, so the licence sits on the Brreg half
 * only (spec v3.8 B2). */
const NLOD_URL = {
  nb: 'https://data.norge.no/nlod/no/2.0',
  en: 'https://data.norge.no/nlod/en/2.0',
} as const

/** The page's last line: version, source code and the data credit (spec v3.8 B2). The version
 * comes from the status query the app already runs at boot, so this costs no request, and it is
 * left out when that fetch failed. */
export function AppFooter() {
  const t = useT()
  const [lang] = useLang()
  const { data: status } = useQuery(statusQuery())

  return (
    <footer className="app-footer">
      <p className="container cluster cluster-sm">
        {status?.version && <span>Hugin {status.version}</span>}
        <a href={REPO_URL} target="_blank" rel="noopener noreferrer">
          GitHub
        </a>
        <span>
          {t('footer.adsCredit')} · {t('footer.companyCredit')} (
          <a href={NLOD_URL[lang]} target="_blank" rel="noopener noreferrer">
            NLOD
          </a>
          )
```

```tsx
import { useRouter } from '@tanstack/react-router'
import {
  createContext,
  type ReactNode,
  useCallback,
  useContext,
  useEffect,
  useMemo,
  useRef,
} from 'react'

interface ReturnFocus {
  /** Call as a link that leaves the page is followed. Remembers the link by its
   * `data-return-focus` value and the history entry it was followed from. */
  remember: (key: string) => void
  /** Call once the page has rendered fresh data. If the page was left and its entry is current
   * again (Back, or a detail's close), focuses the remembered link inside `container`, or
   * `fallback` when the link is gone, and forgets it. Never moves focus the person has already
   * moved, and never scrolls. */
  restore: (container: HTMLElement | null, fallback?: HTMLElement | null) => void
}

const noop = () => {}

const ReturnFocusContext = createContext<ReturnFocus>({ remember: noop, restore: noop })

interface Pending {
  key: string
  /** The history entry the link was followed from. */
  index: number
  /** Set once a navigation away from that entry has resolved. A Ctrl-click that opened a new
   * tab, or a navigation the unsaved-changes guard blocked, never sets it. */
  left: boolean
}

/** Views unmount when their route stops matching (spec v3.8, router change), so focus cannot
 * go back to the same element after Back. This remembers which link was followed, by identity,
 * and the view focuses its new copy once it has rendered. The history entry index keeps it to a
 * real return: reaching the same page through the nav is a new entry and focuses nothing. */
export function ReturnFocusProvider({ children }: { children: ReactNode }) {
  const router = useRouter()
  const pending = useRef<Pending | null>(null)

  useEffect(
    () =>
      router.subscribe('onResolved', ({ toLocation }) => {
        const target = pending.current
        if (target && toLocation.state.__TSR_index !== target.index) target.left = true
      }),
    [router]
  )

  const remember = useCallback(
    (key: string) => {
      pending.current = { key, index: router.history.location.state.__TSR_index, left: false }
    },
    [router]
  )

  const restore = useCallback(
    (container: HTMLElement | null, fallback?: HTMLElement | null) => {
      const target = pending.current
      if (!target?.left || !container) return
      if (router.history.location.state.__TSR_index !== target.index) return
      pending.current = null
      // The person is already somewhere: leave them there.
      const active = document.activeElement
      if (active && active !== document.body) return
      const link = [...container.querySelectorAll<HTMLElement>('[data-return-focus]')].find(
        (el) => el.dataset.returnFocus === target.key
      )
      // The router restores this page's scroll position; focusing must not move it.
      ;(link ?? fallback)?.focus({ preventScroll: true })
    },
    [router]
  )

  const value = useMemo(() => ({ remember, restore }), [remember, restore])
  return <ReturnFocusContext.Provider value={value}>{children}</ReturnFocusContext.Provider>
}

export function useReturnFocus(): ReturnFocus {
  return useContext(ReturnFocusContext)
}
```

## Stress-test record (2026-10-14)

Five lenses: security, privacy, accessibility, legal, loopholes. Every finding is folded into the
tasks above.

**Applied**
1. 🟠 Accessibility: opening a company dropped focus on `<body>` (true from the list on main;
   Task 4 adds a second way in). New Task 5: the detail focuses its heading once per opened
   company. Proof: two app tests, and the Task 7 keyboard walk.
2. 🟠 Accessibility: a company no longer in the digest left focus on `<body>` after Back. The
   card heading is now the fallback. Proof: «a company gone from the fresh digest» and the
   provider's fallback test.
3. 🟠 Loophole: a Ctrl-click (new tab) or a blocked navigation remembered the link without
   leaving, so a later refetch on the same page would have pulled focus onto it. The provider
   now sets `left` from the router's `onResolved` event and restores only after a real return.
   Proof: «does nothing when the page was never left».
4. 🟡 Loophole: Enter held down on Tilbake could go back twice, out of the app from a visit's
   first page. One close per opened company. Proof: «a repeated close», checked red once with
   the guard commented out.

**Adapted**
1. 🟠 Loophole: restoring on cached data focused a link that the remount's refetch could remove
   a moment later. The obvious fix was to drop the stale cache on Back; waiting for
   `!isFetching` before restoring is one condition in the view and keeps the instant cached
   render. Proof: «a company gone from the fresh digest» (the cached copy still has the link).
2. 🟡 Accessibility: a slow refetch could restore focus after the person had already started
   tabbing. Rather than a timeout, `restore` leaves focus alone whenever it is not on `<body>`.
   Proof: «leaves focus alone when the person has already moved it».

**Security, privacy, legal: clean.** No new endpoint, field or dependency. Orgnr reaches the
DOM only through the router's `href` and a `data-` attribute matched by string compare, never a
selector. The version renders as React text. External links keep `noopener noreferrer`, and the
data credit is the spec's, sources read 2026-10-02.

**Considered and rejected**
- **A new-tab hint on the footer links.** No external link in Hugin has one. Adding it in one
  place makes them inconsistent; an app-wide hint is its own change.
- **Keeping the return-focus memory across a reload** (sessionStorage). A reload on a detail is
  rare, and after it Tilbake still lands on the right page, with focus starting at the top.
- **Not focusing the heading on a cold deep link.** The heading is the first thing on that page
  anyway, and one rule for every way in is simpler to test and to reason about.
- **The router's `onRendered` event instead of the view's effect.** It fires when the route has
  rendered, not when its query data has, so the link may not exist yet.
- **The version string discloses the build.** Already rejected in the spec's stress test: the
  repo and releases are public.
