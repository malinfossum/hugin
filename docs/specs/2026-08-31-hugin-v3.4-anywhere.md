# Hugin v3.4 — "anywhere": discovery config from the UI

2026-08-31. Decisions locked with Malin: product identity is **developer-first, adaptable** —
"every job in Norway visible" is dropped as a goal (it would clone arbeidsplassen.no, the keyword
net doesn't generalize, and all-NACE ≈ 1M+ enheter breaks the architecture). The arc is
**v3.4 anywhere** (this spec) then **v3.5 adaptable** (NACE/keywords/categories as an editable
focus profile with the IT set as curated default). Category focus stays render-side in this wave.

First-run region choice = **scope + lens** (writes server discovery scope AND seeds the render
focus). Kommune-level picking stays in (checkboxes cascading under the fylke — the scope layer
already handles individual kommuner; today's default config *is* four hand-picked kommuner).
Scope changes auto-sync immediately. This wave ships as release **v3.4.0** (also tags the slate
publish that is currently ahead of v3.3.0).

## Part A — config-write API

Existing security model throughout: loopback bind, Host allowlist, writes need `X-Hugin: 1`,
no CORS.

1. **`GET /api/kommuner`** — the db kommune register as `[{ number, name }]`. If the register
   is empty (fresh install, pre-first-sync), fetch Brreg `/kommuner` live as a best-effort
   fallback; if that also fails, return the failure honestly (the dialog degrades, Part B).
2. **`GET /api/config/discovery`** — `{ municipalities: [{ name, number }], fylker: [],
   allOfNorway: bool }` read fresh from hugin.json.
3. **`PUT /api/config/discovery`** — accepts **numbers only**: `{ municipalityNumbers: [],
   fylker: [], allOfNorway: bool }` (stress-test: names never come from the client). The server
   validates every kommune number and fylke prefix against the register — any unknown number is
   a 400 with a reason, nothing written — and derives display names from the register.
   - **Read-modify-write on the raw JSON document** (JsonNode): hugin.json is re-read at write
     time and only the three discovery keys are replaced, so keywords, navToken, linkouts and
     any hand-edited or unknown fields round-trip untouched. A test pins this byte-behavior
     outside the three keys.
   - **Atomic + backed up:** write `hugin.json.bak` first, then temp-file-and-replace. A failed
     write never corrupts the config (500, file untouched).
   - **No sync guard:** sync holds a per-run config snapshot (Part C), so writing during a
     running sync is safe. PUT always succeeds; there is no 409. (Two-tab last-write-wins is
     accepted — single-user loopback tool, no ETag.)

## Part B — web UI

- **First-run dialog v2** (same dialog conventions as v3.3): the region step becomes scope+lens.
  Fylke select (All of Norway / static fylke list). Choosing a fylke reveals its kommuner as
  checkboxes from `GET /api/kommuner` — none checked = the whole fylke. Checkbox group is a
  `fieldset` + `legend` labeled with the fylke name; targets ≥ 44 px (stress-test).
  - **Start** = `PUT /api/config/discovery` + seed the localStorage focus + trigger sync (the
    existing SyncHeader shows progress). **Esc still closes without saving** — config untouched,
    prompt returns next launch, and on a fresh install the held boot sync (Part C) then runs
    with the config defaults.
  - **PUT failure:** the focus still saves locally (lens works), the dialog shows a retryable
    error in a `role="alert"` region (stress-test), config untouched.
  - **`/api/kommuner` unreachable:** degrade to the static fylke list — fylke granularity only,
    kommune refinement available later in Settings.
- **Settings** gains a «Dekning» / "Coverage" section: the same fylke→kommune cascade, showing
  the current server scope, with a save that PUTs and auto-syncs. Success announces via the
  existing live-region pattern («Lagret — synkroniserer…» / "Saved — syncing…"). Copy makes the
  two layers explicit: coverage = what gets fetched, focus («Fokus», unchanged) = what you see.
- Companies filters are unchanged (they are the lens). Category checkboxes keep their v3.3
  render-side behavior until v3.5. New i18n keys land in both tables (key-parity test covers).

## Part C — sync changes

- **Per-run config read:** SyncService builds MunicipalityScope (and reads keywords/categories/
  NACE) from a **fresh ConfigLoader read at the start of every run** instead of the startup
  snapshot. No restart is ever needed for a scope change. Console and Api hosts both.
- **Fresh-install boot holds for first-run (stress-test, the load-bearing fix):** when the API
  host starts with **no existing db**, the boot auto-sync **waits until the first-run dialog
  resolves** (saved or dismissed) instead of racing it with the default Innlandet config. The
  UI signals resolution by triggering sync (save path) or via a lightweight
  `POST /api/first-run-dismissed` (Esc path) that releases the held boot sync with config
  defaults. Existing installs (db present) keep today's immediate boot sync.
- **≥10k hardening — date-range bisection:** when any Brreg chunk reports totalElements at or
  above the 10k deep-pagination window, that chunk re-runs **recursively bisected by
  registration-date range** (generic; NACE sub-code lists rejected — taxonomy-fragile, «62.010»
  returns zero under SN2025). Boundaries are explicitly half-open (`[from, mid)` / `[mid, to)`)
  so slices partition; a fake-Brreg test pins that the union of bisected slices equals the
  unsplit set (stress-test). Depth-capped; hitting the cap logs a visible warning naming the
  slice that still overflowed. Existing partial-progress chunk semantics stay.
- **Narrowing never deletes:** shrinking scope stops fetching outside it; already-synced
  companies/ads stay in the db and the focus lens hides untracked ones (v3.3 bypass rule —
  tracked/starred can never vanish).

## Part D — testing

- **Round-trip:** hand-edited hugin.json with unknown fields survives PUT byte-for-byte outside
  the three discovery keys.
- **Validation:** unknown kommune/fylke numbers → 400, file untouched; `X-Hugin` guard.
- **Bisection:** fake Brreg reporting >10k → slices partition (union = unsplit set), half-open
  boundaries, depth-cap warning path.
- **Per-run reload:** config edited between two syncs → second sync uses the new scope, no
  restart.
- **Boot hold:** fresh install (no db) does not sync before first-run resolution; save and
  dismiss paths both release it; existing-db boot syncs immediately.
- **Web:** dialog v2 (cascade, Esc, PUT-failure alert, kommuner-endpoint fallback), Settings
  coverage section (save, announce), i18n key parity.

## Stress-test record (2026-08-31)

Run pre-implementation, four lenses. Folded in: boot-sync/first-run race (🔴 → boot hold),
409 removal, numbers-only PUT, bisection partition proof, a11y pins (fieldset/legend + 44px,
`role="alert"`, live-region save announce). Accepted: two-tab lost-update (no ETag),
keep-and-hide on narrowing, no NACE sub-code chunking, reload-mid-first-run reappearing dialog.
Privacy clean — only new call is public Brreg `/kommuner`; region choices stay local.
