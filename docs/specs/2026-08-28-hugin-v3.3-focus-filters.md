# Hugin v3.3 — focus filters + polish

2026-08-28. Decisions locked with Malin: the first-run prompt asks **region + category**; the saved
choice applies **app-wide** (Companies + dashboard); persisted **in the browser** (localStorage, like
the Applications sort choice); the small-bug batch ships **in the same wave, fixes first, own commits**.

## Part A — bug batch (before the features, one commit per numbered item where practical)

1. **Pluralization.** No plural engine exists (`interpolate` is a plain `{key}` replace) and none is
   added — each affected string gets an explicit `*One` sibling key chosen in code at `n === 1`
   (the key-parity test keeps both tables aligned):
   - `trenger.deadlineInDays` → `trenger.deadlineInOneDay` («frist om 1 dag» / "due in 1 day")
   - `frister.daysBadge` → `frister.dayBadgeOne` («1 dag» / "1 day")
   - `companies.count` → `companies.countOne` («1 bedrift» / "1 company")
2. **Companies count counts what you see.** `companies.count` renders `visibleGroups.length`
   (companies as listed, branches folded into their parent), not the per-unit `filtered.length` —
   the number and the rows can currently disagree.
3. **Dashboard silent failures.** `TrengerHandling`: a failed `/api/ads` currently makes the whole
   section vanish (indistinguishable from "nothing urgent") — it gets the FristerList
   loadError + retry pattern. `SourcesCard`: same pattern for `/api/sources`. `SyncHeader`: the
   *initial* `/api/status` failure shows an error state; the running-sync poll stays silent by
   design.
4. **Settings parked bundle** (the recorded post-merge follow-up): sources load-error + retry, and
   live-region announces on add/edit/remove/reorder success.
5. **Races.** Star toggle in Applications disables while its PUT is in flight. EksportView gets a
   stale-response guard (request token; only the latest response renders).
6. **API robustness** (two deferred minors): `POST /api/sources/reorder` null-guards `request.Ids`
   (400, not 500); `PUT /api/sources/{id}` re-fetch drops the null-forgiving `!` (concurrent
   delete → 404, not NRE).
7. **hugin-web/README.md** replaces the Vite boilerplate with a short real README (what it is, dev
   commands, where the design system comes from).

## Part B — fylke → kommune cascading filter (Companies)

- Every company row already carries the 4-digit `kommune` number; its first two digits are the
  fylke number (the sync code already chunks by this prefix). The only missing piece is a
  **static fylkesnummer → name map** (2024 set, 15 entries) — new `hugin-web/src/fylker.ts`, with
  `fylkeOf(kommunenummer)` = first two digits. Unknown prefixes fail open under the raw number.
- BedrifterView gains a **Fylke select** ahead of the Kommune select. Options are the fylker
  actually present in the loaded companies (labeled from the map). Choosing a fylke narrows both
  the company list and the Kommune select's options; changing fylke clears an incompatible kommune
  choice. Purely client-side; no API change.
- New i18n keys: `companies.fylke` («Fylke» / "County"), option-all reuses `common.all`.

## Part C — first-run focus + persisted app-wide filter

- **Storage:** localStorage key `hugin-focus`, JSON `{ v: 1, fylke: string|null, kommune:
  string|null, categories: string[] }`. Empty `categories` = all. On read, the value is
  **shape-validated**, not just parsed: `v === 1`, correct field types, and a stored kommune must
  belong to the stored fylke (prefix match) — anything invalid is treated as unanswered
  (stress-test #4). Writes are wrapped in try/catch (storage may be blocked); in that case the
  prompt simply reappears next launch.
- **Ownership:** a `FocusContext` provided by App is the **single reactive owner** of the focus
  value; localStorage only hydrates it on boot and persists on change. All consumers (Companies,
  dashboard, Settings) read the context, so a change anywhere applies everywhere immediately
  (stress-test #3).
- **First-run dialog:** on app mount with no stored focus, an accessible modal (same dialog
  conventions as ConfirmDialog: focus trap, `aria-labelledby`) asks what to follow:
  - Region: fylke select only (All of Norway / the static fylke list). No kommune control here —
    the dialog opens before any company data is loaded; kommune refinement lives in the Companies
    filters and Settings (stress-test #2).
  - Category: checkboxes in a `fieldset` + `legend` for the known level-2 categories
    («Utvikling», «Drift, vedlikehold») — none checked = follow everything (stress-test #6).
  - One primary action («Start» / "Start") saves the choice — including an all-open choice, so the
    prompt never nags again. **Esc closes without saving** (the prompt returns next launch —
    explicit, bounded nagging). Initial focus lands on the dialog heading; on close, focus moves
    to `<main>` — there is no trigger element to return to (stress-test #5).
- **Where it applies (the focus lens):**
  - *Companies:* the saved fylke/kommune seed the Part-B filters' initial values. Manual filter
    changes in the view **write back** to the stored focus (that is the "saved the next time you
    enter" behavior). Search text and website filter stay per-session.
  - *Dashboard:* FristerList and TrengerHandling filter ads by focus — category match on the ad's
    `category` string (contains any selected category), region match on the ad's `kommune` prefix.
    Ads with no category or no kommune **fail open** (house rule: uncategorized fails open).
    **Bypass rule (stress-test #1):** any ad with a pipeline status or a star is exempt from the
    focus filter — focus narrows the *untracked* stream only, so a deliberately tracked deadline
    can never disappear.
  - *Nytt siden sist stays unfiltered* — it is the review list; hiding new arrivals there would
    silently shrink the baseline-advance decision.
- **Settings:** a «Fokus» / "Focus" section with the same controls (fylke, kommune, categories)
  plus a reset action («Vis oppstartsvalget igjen» / "Show the first-run choice again") that clears
  the stored key. Save and reset announce via the live region, like the other Settings mutations
  (stress-test #6). Changing fylke here clears an incompatible kommune, same as in Companies.
- **i18n:** all new strings land in both tables (key-parity test enforces).

## Out of scope

- Database persistence of the focus (localStorage v1; graduate only if a real need appears).
- CLI parity for focus/filters; deadline-sort on Applications; the CLI/dashboard seams.
